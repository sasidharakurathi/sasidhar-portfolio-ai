## Technical Expertise

**Backend**: I design APIs following a layered, async-first philosophy. In Project-T, I built a FastAPI server that manages persistent TCP-over-HTTP/2 tunnels, using Hypercorn with h2c support for low-latency header compression and multiplexing. Startup/shutdown of background TCP server tasks is coordinated via FastAPI lifespans to guarantee clean resource teardown. In AI-Interviewer, I combined FastAPI for REST/WebSocket API management with Django Channels for reliable real-time WebSocket signaling during live video sessions. State is persisted via SQLAlchemy ORM with Alembic migrations (Project-T) and a robust UUID-keyed MySQL schema (AI-Interviewer), providing both session continuity and audit logs. Concurrency is handled through Python's asyncio — heavy tasks like Whisper transcription or LLM inference run in background thread pools (asyncio.to_thread) so the API event loop stays unblocked.

**Ai Systems**: I build multi-stage AI pipelines that combine retrieval precision with semantic depth. In Axon-File-Manager, the 'Neural Search' engine runs a four-stage pipeline: (1) Dual Retrieval — BM25 keyword search fused with dense vector search against a Qdrant vector store using BAAI/bge-base embeddings, merged via Reciprocal Rank Fusion (RRF); (2) HyDE Query Expansion — a hypothetical document is generated for the query to improve vector recall on vague inputs; (3) Cross-Encoder Re-ranking — a re-ranker model scores the fused candidate set, ensuring the most semantically relevant files surface first; (4) KeyBERT Keyword Extraction — key concepts are auto-extracted at indexing time for richer BM25 recall. In Repo-Scribe, I implemented RAG without a vector database: the VS Code extension scans a project's docs/ folder, chunks Markdown style guides, and injects the most relevant conventions directly into the Gemini prompt context alongside the git diff. LLM orchestration across projects is provider-agnostic — I toggle between cloud (Google Gemini/gemma-3-27b) and fully local (Ollama/Llama 3.2) depending on privacy requirements.

**Security**: My security approach is built on three pillars. First, biometric authentication: in ATS, I integrated face recognition (dlib/OpenCV) for admin login, with multiprocessing-based parallel face encoding and a modification-timestamp cache to avoid re-encoding unchanged images — making biometric checks fast without sacrificing accuracy. Second, 'Bring Your Own Key' (BYOK) patterns: in Prompt-Polish, no API keys are ever sent to a backend. The Gemini API key is stored exclusively in chrome.storage.sync and API calls go directly from the browser to Google — a zero-backend, privacy-first architecture where the operator never sees user credentials. Third, air-gapped deployment security: in venvdrop, a SHA-256 integrity manifest is generated at pack time and verified at unpack time for every bundled file, and a platform descriptor (bundle_meta.json) embeds OS/CPU architecture/Python version metadata that blocks incompatible cross-platform deployments — preventing silent runtime failures in secure, offline environments.

**Devops**: My DevOps approach centers on self-contained, reproducible deployments. In venvdrop, I achieved zero runtime dependencies by building the entire CLI on Python's standard library only (ast, hashlib, http.server, socket, argparse) — no pip, no requests, no external packages. This makes the tool installable in the most restricted environments and auditable without a dependency graph. For cross-platform desktop bundling, RoboSwift uses Tauri 2 with a Rust backend: npm run tauri build compiles a production binary with a ~10 MB footprint, embedding the React frontend into a native OS installer for Windows. In Project-T, the desktop client is similarly bundled via Tauri for Windows/macOS/Linux. Axon-File-Manager uses PyInstaller to package the Python AI desktop app (with embedded models) as a standalone executable — handling the complexity of shipping heavy ML dependencies (Qdrant, sentence-transformers, KeyBERT) without requiring users to set up a Python environment. Local environment automation follows setup-script patterns with embedded platform guards (OS, CPU arch, Python version checks) to ensure consistent bootstrapping.

## Project Faqs

### FAQS for Project: VirtuHire-AI
**Faqs**:
- **Question**: How does VirtuHire generate interview questions?
- **Answer**: VirtuHire uses LLMs like Google Gemini to generate context-aware interview questions based on job descriptions and candidate profiles. The system feeds structured inputs like skills, experience level, and role requirements into the model, ensuring that the generated questions are relevant and adaptive rather than generic.

- **Question**: How do you handle real-time proctoring in VirtuHire?
- **Answer**: The frontend captures video frames and sends them as base64 images to the backend. The backend processes these frames using computer vision models like YOLOv8 and MediaPipe to detect objects like phones and track face orientation, gaze, and presence. Alerts are generated based on predefined rules.

- **Question**: How did you handle heavy AI processing without slowing the system?
- **Answer**: I implemented an asynchronous background worker system. Tasks like transcription and analysis are processed outside the main request cycle, preventing API blocking. This ensures the system remains responsive even during heavy AI workloads.


### FAQS for Project: Project-T
**Faqs**:
- **Question**: How does your tunneling system work?
- **Answer**: Project-T establishes persistent connections between a client and server. The server manages incoming requests and routes them through these tunnels to the client. It supports HTTP/1.1, HTTP/2, and raw TCP, allowing flexible traffic forwarding.

- **Question**: How do you handle concurrency in Project-T?
- **Answer**: Concurrency is managed using Python asyncio. The FastAPI server uses lifespan events to start and manage background TCP server tasks, ensuring proper lifecycle handling and non-blocking operations.

- **Question**: Why did you choose HTTP/2 support?
- **Answer**: HTTP/2 provides multiplexing and header compression, which improves performance and reduces latency. It allows multiple streams over a single connection, making tunneling more efficient compared to HTTP/1.1.


### FAQS for Project: Axon-File-Manager
**Faqs**:
- **Question**: How does the search system work in Axon File Manager?
- **Answer**: It uses a multi-stage pipeline combining BM25 keyword search and vector-based semantic search. The results are merged using Reciprocal Rank Fusion and then re-ranked using a cross-encoder model to ensure the most relevant results appear first.

- **Question**: What is the role of HyDE in your system?
- **Answer**: HyDE generates a hypothetical document based on the query. This improves vector search by creating richer semantic representations, especially for vague or short queries.

- **Question**: How do you handle performance with multiple AI models?
- **Answer**: I load models asynchronously using background threads and use a staged pipeline so expensive operations like re-ranking are applied only to a filtered subset of results.


### FAQS for Project: VenvDrop
**Faqs**:
- **Question**: How does VenvDrop ensure portability across systems?
- **Answer**: It bundles a Python environment along with a platform metadata file that includes OS, CPU architecture, and Python version. During unpacking, it verifies compatibility before deployment.

- **Question**: How does the wireless transfer system work?
- **Answer**: It uses UDP multicast for device discovery and a Python-based HTTP server for file transfer. A PIN-based authentication ensures secure transfer within the local network.

- **Question**: How do you ensure integrity of transferred files?
- **Answer**: Each file is hashed using SHA-256 during packaging, and the hashes are verified during unpacking to ensure no corruption or tampering.

## System Design Faqs

**Question**: How would you design a scalable AI interview system?

**Answer**: I would separate the system into multiple services — a real-time communication service for video/audio, an AI processing service for transcription and analysis, and a core backend for session management. I’d use message queues for async processing and ensure stateless APIs for scalability.


**Question**: How do you design systems that handle heavy AI workloads?

**Answer**: I avoid running AI tasks in request-response cycles. Instead, I use background workers, queues, and async processing. I also consider batching, caching, and model optimization to reduce compute overhead.


**Question**: How do you ensure reliability in distributed systems?

**Answer**: I focus on proper error handling, retries, logging, and fallback mechanisms. I also design systems to be resilient by avoiding single points of failure and ensuring components can recover independently.


**Question**: How do you handle scaling in backend systems?

**Answer**: I design stateless APIs so they can scale horizontally. I also optimize database queries, use caching where needed, and offload heavy processing to background systems.


**Question**: How do you approach API design?

**Answer**: I design APIs with clear separation of concerns, consistent structure, and proper validation. I also think about versioning, error handling, and scalability from the beginning.


**Question**: How do you debug production issues?

**Answer**: I rely on logs, monitoring, and reproducible scenarios. I first identify where the failure occurs, then trace back the data flow to find the root cause instead of applying quick fixes.
